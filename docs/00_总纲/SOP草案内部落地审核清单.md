# SOP 草案内部落地审核清单（可执行路线）

> 通用建议，供企业实验室负责人在内部部署公开 SOP 草案时使用。不是安全审核报告、设备制造商说明书或正式审批件。

## 阶段 A：文件和岗位确认

- [ ] 列出所有需要覆盖的实验任务、装置、测试和风险等级。
- [ ] 确认每份 SOP 的负责人、操作者、复核人、最终批准人，存在职责冲突时指定独立复核。
- [ ] 建立文件编号、版本、密级、适用范围、培训与历史记录管理规则。
- [ ] 将 SOP-002 保持原样，后续如确需修订应单独申请；此轮不得改动。

## 阶段 B：现场适用性与关键技术边界

- [ ] 从设备制造商文件、铭牌、检验合格证明和实际风险分析获得设备允许边界及保护方式。
- [ ] 确认配方、工艺参数、取样点、计量误差、校准/检测周期仅出现在内控文件中，且有审核依据。
- [ ] 对所有涉及压力、反应热、放大、易燃挥发物、气瓶或特殊物料的环节实施专项风险复核。
- [ ] 明确危险废物识别、分区、容器、标签、合规交接和突发事件处置。

## 阶段 C：记录与能力验证

- [ ] 使用空白表单做一次模拟记录，以检查字段是否足以追溯任务/样品/仪器/方法/原始数据/结论。
- [ ] 完成岗位培训、现场演示及考核，不以文件阅读替代实际能力验证。
- [ ] 对方法、测量系统和必要的质量控制开展确认；结果不满足要求不得凭主观经验放行。
- [ ] 进行一次异常场景桌面演练（例如设备失效、断水断电、样品标签不明），验证升级和停用路径。

## 阶段 D：批准、试用、复查

- [ ] 技术、安全、文件控制等授权审核人关闭待确认事项。
- [ ] 颁布内部受控生效版本并完成旧版回收；GitHub 公共草案继续保留草案状态。
- [ ] 首次应用后检查记录完整性、偏差频率、工作人员反馈及不可执行节点。
- [ ] 任何跨版本修订均保留变更说明、培训影响评估和验证证据。

## 可接受的落地成果（建议，不是认证通过标准）

| 领域 | 可证明成果 |
| --- | --- |
| 文件 | 受控清单、签批记录、有效版本及发放回收记录 |
| 人员 | 培训考核、岗位授权、独立复核职责表 |
| 设备 | 维护校准计划、状态标识、保护验证、故障关闭记录 |
| 物料和样品 | 批次及标识、出入库、采样移交和处置记录 |
| 数据 | 原始文件、可复算公式、审核和更正轨迹 |
| 风险 | 风险评估、应急程序、隐患整改和CAPA证据 |
