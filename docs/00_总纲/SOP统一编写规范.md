# SOP 统一编写规范

> 版本：V0.2（草案）｜审批状态：未批准｜编制日期：2026-11-09

## 一、统一结构

各类 SOP 应采用统一的章节、审批、记录与归档结构，具体技术流程按业务适用范围编制。文件组成及章节顺序如下：

| 组成 | 必要内容 |
| --- | --- |
| 文件首页 | 文件编号、版本、草案状态、生效日期 |
| 编制与审批 | 编制、技术审核、必要的安全/质量审核、批准 |
| 修订记录 | 版本、日期、内容、状态 |
| 一、目的 | 说明建立文件的目标 |
| 二、适用范围 | 适用业务、人员、排除事项 |
| 三、角色与职责 | 角色表、执行/复核/审批权限 |
| 四、术语和定义 | 术语与附录 C 对应 |
| 五、作业流程 | （一）流程总图、（二）流程节点对照、（三）准备、实际工序、结束交接 |
| 六、关键控制点与工艺参数 | 阶段检查、判定依据、记录；非工艺文件用业务控制标准 |
| 七、记录要求 | 记录表单、填写规则、字段说明、归档 |
| 八、异常与偏差处理 | 风险控制、报告、调查、复核与恢复 |
| 九、安全与环保 | 按实际风险和法规识别安全与保密要求 |
| 十、注意事项清单 | 本主题易错事项 |
| 十一、设备维护与报修 | 如无设备或系统，明确“不适用” |
| 十二、相关文件 | 受控文件、外部参考、适用限制 |
| 十三、附则 | 生效、复审、审批和变更要求 |
| 附录 A | 待确认事项清单 |
| 附录 B | 可维护的流程节点表 |
| 附录 C | 术语和定义对照表 |
| 附录 D | 可选的版本迁移、专项风险说明 |

## 二、Markdown 排版规则

1. 文件标题使用 `# SOP-XXX 中文名称标准作业程序`。
2. 十三章使用 `## 一、` 至 `## 十三、`；第五、七章的分节使用 `### （一）`，细分步骤使用 **1.** 或 **（1）**。
3. 检查表采用 Markdown 表格，并在正文中标注“表 1”“表 2”等表号；编号不得重复，跨段引用应同步更新。
4. 流程图使用 GitHub 可显示的 Mermaid `flowchart TD`，附录 B 保留同一逻辑的文字节点表；修改任一处须同步更新另一处。
5. 用 **【待确认】** 表示没有来源的事实、审批、数字或周期。不能凭经验填写压力、温度、浓度、放热、抽样次数或验收标准。
6. 复核关口应写清楚“做什么、由谁做、怎样证明、失败怎么办”，不能只有“按规定执行”四字。
7. 保留原版本的专业内容、来源和限制；格式调整不得静默删除原来已经存在的记录要求或必要步骤。

## 三、专业差异

- **实验类**：可按准备、配料、乳化、入料、反应、后处理、出料、交检、清洗排布，但只有实际适用的步骤才应出现。
- **检测类**：按样品识别、方法确认、仪器/标样状态、质控、实测、复核、报告、留样/归档。
- **巡检类**：按点位、状态、实测、缺陷、临时措施、整改、验收、交接。
- **设备类**：按设备档案、停机隔离、维护方案、维修、功能验证、复用批准。
- **支撑类**：按申请、审核、批准、实施、监督、更新、归档；不凭空增加化学操作步骤。

## 四、资料保护和版本控制

- SOP-002 是根据原始 Word 完整转写的文档，**含原件标注的内部内容**。仓库当前为公开仓库，具体保密授权应由文档所有者评估；后续将内容改为私有不等于可以无视 Git 历史。
- 除明确获得公开授权的文档外，不得提交真实配方、实验批号、检测结果、员工信息、客户资料、凭据或内部工艺参数。
- 现行草案版本为：SOP-002 V0.14；SOP-001 及 SOP-003～020 V0.4。各文件的实际审批与生效信息以内部受控台账为准。
- 文件的有效状态依据内部审批程序确定；GitHub 仓库版本变动不构成文件批准。
